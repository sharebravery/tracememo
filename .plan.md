### Library (AddressRow)
- Already shows per-chain confidence ✓ (from previous round)
- Add `t()` for labels

## 2. Copy-address hook

### `useCopyAddress` hook (pages/side-panel/src/hooks/use-copy-address.ts)
- `copy(text)` -> tries `navigator.clipboard.writeText`, sets state `copied`/`failed`
- 1.5s timer, cleared on unmount, consecutive clicks reset timer
- Returns `{ copy, status: 'idle' | 'copied' | 'failed' }`
- Used in AddressRow, CurrentPageView, RecordEditor

### `<CopyAddress>` component
- Renders address + copy icon + status feedback
- Keyboard accessible (button with aria-label)

### Strings to extract (via `t('key')`)
- Manifest: extensionName, extensionDescription, openSidePanel (already exist)
- Tabs: current_page, library, settings

- Data: backup_title, export, import, import_preview, confirm_import, clear, confirm_clear, backup_first, delete_all
- Copy: copied, copy_failed
- States: loading, saving, empty, error
- Badge: private_cue, no_context_pattern (with $1 = chain name)

### Using `t()` in components
- Import `{ t }` from `@extension/i18n` in each component
- Replace hardcoded English strings with `t('key')` or `t('key', [substitution])`
- Content script badge: cannot use `t()` (no chrome.i18n in content script context at build time) — use hardcoded English for the badge text (acceptable: the badge is a compact inline element, and Chrome's i18n API works at runtime via `chrome.i18n.getMessage` which IS available in content scripts)

Actually, `chrome.i18n.getMessage` IS available in content scripts. So the badge CAN use `chrome.i18n.getMessage(key, substitutions)` directly. The `t()` function in production mode just calls `chrome.i18n.getMessage`. So content script can import and use `t()` from `@extension/i18n`.
